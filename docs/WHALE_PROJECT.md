# 鲸鱼娘 · 本机微信助手

本项目以当前 WeChatGirl 系统为基础，整合用户自己的鲸鱼娘功能。人格、跨聊天人物记忆、音乐、唱歌和原生语音气泡保持在同一控制台管理。原有组件的许可证和作者说明保留。

## 两种文字发送方式

在侧栏「发送模式」独立页面选择并保存，新的发送使用所选模式；已经提交给微信的消息可能继续完成。新手引导也包含对应配置，后续可选功能的教程见 [配置入口说明](ONBOARDING.md)。

- 原生发送：默认方式，使用现有发送组件。
- 鲸鱼娘前台发送：本项目独立编写的 Windows UI Automation 组件；借鉴旧项目的串行发送、当前聊天快速路径、点击收藏表情与超时防重复思路。无需旧项目、Python 或旧项目 SDK。

前台方式按已验证的允许聊天找到唯一名称，再读取微信控件打开对应聊天。操作前核对窗口、输入框名称及焦点，不覆盖用户已有草稿；目标不明确时停止。微信需要打开，可能切换窗口。

| 功能 | 前台模式 | Hook 模式 |
| --- | --- | --- |
| 文字 | 微信界面发送 | 支持 |
| 表情 | 点击当前可见的随机收藏表情，不能指定内容 | 支持指定表情 |
| 原生 @ 提醒 | 停用，改为普通文字称呼 | 支持 |
| 语音气泡、歌曲语音 | 停用；声音插件工具不提供给模型 | 支持 |
| 图片、文件、其他 Hook 发送 | 停用 | 支持 |
| 音乐搜索、网易云登录、本机曲库 | 保留 | 保留 |

前台模式在统一接口处拦截所有 Hook 发送路由，只允许只读健康检查。已有语音或文件任务在执行前再检查模式，防止切换后继续投递；不自动回退 Hook。发送设置、声音插件配置与成品音乐均保留，切回 Hook 后可恢复新请求，失败或不确定的旧任务不会自行重发。

## 账号风险

前台方式以界面模拟操作发送，对发送流程的接入较少；Hook 方式功能完整、回复方便，但接入客户端更深。没有可靠数据能证明两者的封号概率高低，都不能保证账号安全。本开关只隔离发送，不卸载已加载的 Hook，也不改变消息读取方式，因此不能宣称切换后完全无 Hook 或封号概率已降低。

发送前持久化投递编号，数据库收到微信服务器消息编号才算确认。超时、重启或切换通道都不会让已尝试的消息重复提交。「检查前台组件」只读取控件，不发送消息。

## 页面显示

导航、标题、卡片文字立即可读，取消逐块透明度级联及文字模糊；只保留 140 毫秒的轻微位移。页面指标直接显示真实数值。读取后台数据的等待仍会明确显示。
