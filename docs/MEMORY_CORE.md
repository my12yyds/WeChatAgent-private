# 聊天连续性与人物记忆

## 为什么上下文占用一直很小

聊天模式使用“本地完整档案 + 有限近期窗口”，每次请求替换近期窗口，而非把全部 DSH 事件反复发送。因此 DSH 的占用百分比可能保持在较低范围，不能据此判断是否保存了记忆。旧版迁移预设只有最近 8 条、4000 字符，并且窗口模式没有自动注入已有摘要，容易产生短期遗忘。

新安装与缺少历史配置的迁移使用最近 40 条、12000 字符，关闭“冷唤醒时清空窗口”。明确配置过的安装不会被迁移函数强制覆盖，可在设置中按需调整。范围是消息条数，不是对话轮数；长消息仍可能受到字符预算限制。

## 现在怎样记住

1. **近期原文**：持续保留双方近期发言、引用关系和发送状态；群成员带有稳定身份标识，昵称只用于展示。
2. **每轮续聊资料**：窗口外最近 200 条档案中，挑选最多 8 条明确本人陈述；同时自动查询当前发言相关的本聊天档案，最多补充 4 个片段，并注入已有摘要。每条保留来源编号和说话人，不以同名合并人物。
3. **滚动摘要**：窗口外累计至少 12 条待整理记录，且距上一摘要至少 2 分钟时，在回复后启动一个后台摘要任务。全局一次只运行一个，使用该聊天选中的 DSH 模型，因此会消耗该模型额度。摘要必须引用真实档案编号；失败、取消或切换账号时不提交错误摘要，原文仍可检索。自动整理不阻塞回复，不保证每轮都有新摘要。
4. **长期人物事实**：人物插件在其已授权的聊天中自动记录明确昵称、偏好、宠物、项目、正在学习或进行的活动，以及明确计划。计划按 7 天失效，其余自动事实沿用 180 天期限；普通问句、假设、引用、转发、敏感资料和权限指令不自动提取。新昵称和明确冲突会替换旧记录。

简短身份事实会优先进入人物召回，中文查询使用重叠双字词匹配。群内多人召回统计按本轮合计，避免最后一个没有记忆的人把数量覆盖为零。“自动记住”与“自动召回”独立生效；关闭自动记住仍可读取已存记忆，关闭自动召回仍可记录新事实。

## 跨聊天怎样区分人

人物 ID 来自当前登录微信账号范围内的真实发送者标识，不来自昵称、自称或模型猜测。当前在场人物的档案身份与人物插件 ID 显式关联；同名不同人保持分开，真实同一个人在改名后仍使用原身份。缺少可靠标识的旧资料不猜测关联。

身份识别与内容共享分开处理：同一个人出现在另一个群，不代表可以公开其私聊内容。默认事实只在来源聊天使用；本人明确允许跨聊天使用的事实才可跨聊天召回，而且来源与目标聊天都必须仍在插件授权范围内。否定共享、撤销授权、账号切换均不会扩大访问范围。

## 查看和验证

在“记忆”页查看人物记录与本地历史摘要；DSH 的“原生压缩摘要”与本地滚动摘要是不同来源。查看页面本身不会生成摘要。修改近期窗口参数通常由下一次请求读取；更新 DSH 内核代码后，需要完整退出 DSH 并重新打开，之后重启 WeChatGirl 服务以加载新宿主代码。仅刷新网页不能替换已加载的后台模块。

隔离测试覆盖：70 条消息后的事实召回、进程重新打开、同名身份隔离、昵称纠正、跨群授权与禁止共享、自动记住/召回独立开关、多人召回统计、摘要来源校验与失败保留原文。测试使用虚构记录和模拟模型，没有向真实聊天发消息或把私人聊天提交给外部记忆平台。规则提取和关键词检索不能理解所有表达；没有证据时应检索或说明未找到，不承诺任何模型永远不遗忘。

- [Mem0 的事实提取、召回与身份过滤](https://github.com/mem0ai/mem0/blob/main/skills/mem0/references/architecture.md)：借鉴按用户标识隔离、事实去重与检索的设计。本项目保留现有 SQLite/JSON 存储，没有新增 Mem0/Letta 服务或上传到第三方记忆平台。

## 人物记忆插件配置（1.2.0）

记忆工作台可直接打开“记忆插件设置”，按自动记录、召回与近期上下文、保留与摘要三组配置。已授权且启用 people-memory 的聊天才使用插件的自动人物记忆、档案补充与后台摘要；禁用后基本聊天历史继续保留。文中窗口和摘要数字是默认值，可在插件中调整，仍受宿主总预算限制。保留天数仅影响新记录；降低容量不删除已有数据。跨聊天召回仍需本人明确同意。升级保留旧设置和权限，新增字段使用默认值；完整重开 DSH 和 WeChatGirl 后加载新宿主能力。
