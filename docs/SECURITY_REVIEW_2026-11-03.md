# 本次信息泄露风险核查

范围：0.5.3 的读取凭据保存、通用插件设置、本机接口、发行归档，以及当前安装中 wx_key.dll 的静态特征。本次没有采集真实密钥、读取聊天正文、运行 DLL 抓取函数，或把组件上传到外部扫描服务；这不是完整渗透测试或恶意软件审计。

## 已确认的问题与边界

- 0.5.3 便携归档和部署清单缺少 wx_key.dll。旧电脑安装中仍留有该文件，掩盖了干净安装的缺件问题。缺件本身不说明发生了信息泄露。
- 通用插件的 secret 字段仅在界面返回值中隐藏，updatePlugin 仍将 settings 写入 config/plugins.json，没有统一的落盘加密。语音识别等插件 API Key 因此可能明文保存；本次没有读取用户的实际设置或密钥值。
- 数据库读取密钥由 reader_setup.py 调用 CryptProtectData，以 userdpapi 格式保存，未使用机器范围保护。DPAPI 通常绑定当前用户及电脑，但不能隔离同一 Windows 用户权限下的恶意程序。参考 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。
- 控制台、读取接口与适配器绑定本机回环地址；接口有令牌校验，控制台另核对 Host、Origin 与跨站请求。本机恶意程序仍可能读取可访问的凭据文件，不能将“仅本机监听”理解为完整安全边界。

## DLL 的静态核查

现有组件为 x64，195072 字节，SHA-256 为 9a2f2c6a09a3219afa4748a5e7e513d99c607173c3112c5afcc888996b98248c，与旧发行组件一致；Windows Authenticode 检查结果为 NotSigned。本项目源码没有包含该二进制的完整实现。未签名本身不证明恶意，但减少了可验证的来源依据。

导入表及可见字符串未发现明显的 WinHTTP、WinINet、Winsock 或 URL 下载调用；存在 GetProcAddress 动态函数解析。未发现明显联网特征不等于不存在隐蔽联网、宿主代发或其他未审计行为。文件哈希只能证明匹配已登记的文件，不能证明它没有恶意行为。

## 明确的数据外发路径

启用外部聊天模型会把对应请求与上下文交给所选模型服务。外接语音识别会向配置的服务发送待转写音频；外接语音合成会发送待合成文本及所选参数。获准运行的第三方插件和 DSH 工具还需按各自权限与网络行为评估。服务端留存和再利用策略不在本次本机代码核查范围内。

不要把 data、config/plugins.json、数据库、完整日志或备份直接发给他人排障。需要排障时仅导出脱敏错误码与版本信息。优先使用可信服务和最少插件权限。

## 本次补件修复的范围

构建脚本新增显式的读取组件复制，并检查固定哈希、x64 DLL 格式、所需导出及部署清单。缺件或文件变化时停止打包；默认从审计基线读取，也可用 -ReaderKeyDll 指定同一已登记组件。组件二进制不加入 Git 源码，不在运行时从未知网站下载。

这些检查解决缺件和文件误换问题，不构成对 DLL 的完整安全认证。以上明文存储结论针对 0.5.3 核查时的实现；后续 0.5.4 已为 API v2 插件整份设置加入 Windows 当前用户 DPAPI 加密与迁移测试，见 [0.5.4 日志](releases/0.5.4.md)。历史备份不自动清理，其他外部软件的凭据存储不在这项修复范围内。发布旧附件的撤换以对应 Release 为准。
