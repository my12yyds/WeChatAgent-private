# 人物记忆工作台与第一批优化

入口为“记忆 → 人物与事实 / 运行诊断 / 长对话评测”。原有群友记忆、压缩记忆和鱼的记事本保留，分类直接位于页面顶部。

## 人物与事实

- 按人物与内容搜索，筛选有效、已忘记、被新陈述替代及已过期的记录；每页最多 12 人。
- 每条显示来源聊天、有效期、共享范围、稳定身份与证据标识，不依昵称合并人物。
- 置顶提高召回优先级，仍受有效期、聊天授权和每轮数量限制，不表示永久保存。
- 纠正事实保留最近 8 个旧版本，并自动改为仅来源聊天使用。不能通过后台编辑直接扩大为跨聊天共享；需要本人在聊天中重新明确授权。
- 撤销共享、忘记、恢复均需在按钮上再次确认。忘记是保留墓碑的软删除，可恢复；被本人新陈述替代的旧事实不能直接恢复。
- 修改使用单条事实修订标识，过期编辑被拒绝；宿主与管理端共享短时写入锁，避免并发覆盖。旧 DSH 写入方式仍在线时，后台修改会要求先完整重开 DSH。

纠正及撤回覆盖会按真实身份屏蔽本轮自动续聊中的旧事实，并将可用纠正作为补充资料；存在覆盖时保守避用旧摘要。聊天档案原文和微信消息不会因此物理删除，历史版本也保留在本机。首次关联不足的旧档案不靠昵称猜测对应身份。旧的独立“查看人物记忆”弹窗兼容保留，新管理操作在工作台进行。

## 运行诊断

展示磁盘代码指纹、DSH 报告的记忆内核与管理接口版本、数据目录是否匹配、近期窗口大小与冷唤醒设置。新内核完成聊天后，还会显示各会话最近一轮的原文条数、字符数、人物召回数、纠正覆盖数和摘要编号。

诊断不返回聊天正文、人格或服务密钥。磁盘指纹不等于进程已加载版本；看到“尚未加载”时，从托盘完整退出 DSH 和 WeChatGirl，再打开。窗口“×”通常仅收起到托盘。

## 长对话评测

选择已允许的聊天，仅借用它的模型设置；场景内容由程序固定生成，全部是虚构人物。支持 100 或 500 条干扰消息，实际经过近期窗口、人物事实与档案召回投影，测试宠物记忆、昵称纠正、同名区分、私聊隔离和否定共享五项。它不是向微信自动聊 500 次，也不是把整个真实聊天上传作评测。

一次最多调用模型 5 次，需主动勾选额度确认。每次模型调用最多 25 秒、256 个输出 token；没有工具权限，不建立真实聊天 agent、不发微信。进度按实际完成项展示，可取消；账号或模型变化会停止后续测试。DSH 缺少专用评测接口时先停止，不把未知请求交给普通会话。

结果保存在当前账号的 `state/memory-evaluations/<账号>/`，重开后可读取最近报告。中断任务不会自动重跑，取消保留已完成项。JSON 格式和期望值严格比对；通过仅代表固定测试场景，不保证模型对所有表达都能正确记忆。

## 备份与回退

本轮修改前已在开发机的项目外 `backups/` 创建私人备份，包含修改前源码（含未提交与未跟踪文件）、Git 历史、已安装应用及其依赖、配置、人设、插件数据、人物/群友记忆和一致性的历史数据库快照；文件校验清单与恢复说明随备份保存。大型语音环境、音色原件和音乐文件留在原数据目录，本轮不会替换它们。

不要把该私人备份上传到仓库。回退时先退出 DSH 和 WeChatGirl，优先恢复程序文件；恢复旧配置或旧记忆之前另存后续新数据，以免覆盖新的聊天。当前数据中的新增事实历史字段向后兼容旧读取格式，但旧进程不具备新写入锁，切勿同时混用旧、新宿主写同一数据目录。

## 验证与后续

本轮自动测试及页面操作使用隔离账号、虚构记忆和模拟模型，未调用真实付费模型、未发真实微信消息。真实模型质量需要在上述评测入口主动运行后判断。混合语义检索、事件约定状态和专用 CosyVoice3 引擎属于后续批次，本轮没有静默部署额外模型。

## 人物记忆插件配置（1.2.0）

记忆工作台可直接打开“记忆插件设置”，按自动记录、召回与近期上下文、保留与摘要三组配置。已授权且启用 people-memory 的聊天才使用插件的自动人物记忆、档案补充与后台摘要；禁用后基本聊天历史继续保留。文中窗口和摘要数字是默认值，可在插件中调整，仍受宿主总预算限制。保留天数仅影响新记录；降低容量不删除已有数据。跨聊天召回仍需本人明确同意。升级保留旧设置和权限，新增字段使用默认值；完整重开 DSH 和 WeChatGirl 后加载新宿主能力。

记忆诊断同时核对分层记忆接口、可配置插件能力及 DSH 数据目录；缺少新版能力或连接到其他目录时，不显示为已加载。

## 可选检索与事件插件

能力目录新增“档案检索助手”和“事件与约定”，分别启用、配置和选择聊天。检索助手仅在调用工具时检索当前聊天最近最多 100 条原文，关键词排序后可选当前模型重排；默认关闭额外模型调用，失败回退关键词证据。它不是全历史向量数据库。事件插件只接受本轮在场人物的直接证据和明确记录请求，区分 planned / completed / cancelled，保留最近 8 次状态变化；不推断计划已完成，不自动发提醒。两个插件均默认未授权。
