# 上游新版微信方案核查（2026-11-04）

结论：不能将现有上游方案直接用于本次核查机器的微信 **4.1.15.56**，也不能据此将 WeChatGirl 标记为支持新版完整收发。继续使用已登记的 4.1.10.27 完整能力组合。

## 核对的来源

- 上游默认分支在核查时为 [38c1060](https://github.com/sourcepro5/WeChatAgent/commit/38c1060ce500a294d69a4a2f9e07ca1b63a08b06)。
- [PR #3：4.1.15.13 原生文字](https://github.com/sourcepro5/WeChatAgent/pull/3) 与 [PR #7：图片和群 @ 底层 API](https://github.com/sourcepro5/WeChatAgent/pull/7) 已合并。
- [4.1.15.13 兼容说明](https://github.com/sourcepro5/WeChatAgent/blob/38c1060ce500a294d69a4a2f9e07ca1b63a08b06/docs/WECHAT_4_1_15_13.md) 记录上游维护者在 2026-10-30 报告实机使用成功，同时明确排除 4.1.15.56 等其他版本。
- [启动修复 cca81d7](https://github.com/sourcepro5/WeChatAgent/commit/cca81d7eb0df140a508d5b2bd0aa6e6778e3dbb3) 为 4.1.15.13 增加先打开配置客户端、等待主进程和核心模块再加载发送组件的流程。

## 能力边界

| 版本 | 本次核查结果 |
| --- | --- |
| 4.1.10.27 x64 | WeChatGirl 当前完整收发及原生表情、文件、语音功能使用的组件版本。仍需账号、组件与权限检查通过。 |
| 4.1.15.13 x64 | 上游提供精确版本的基础文字发送和图片、群 @ 原生 API。不能把这些 API 当作本项目已完成相应投递、模型工具和回执集成。 |
| 4.1.15.56 | 上游已登记 profile 中无对应映射，不能使用 4.1.15.13 的偏移与对象布局。 |

4.1.15.13 组件会核对核心版本、映像大小、发送入口特征及对象布局。其 `nativeStickerSend`、`nativeQuoteSend` 为 false，也不包含本项目针对 4.1.10.27 的原生语音发送扩展。仅把版本判断放开，不能获得这些能力。

WeChatGirl 已保留该版本的原生源码、构建及装载脚本供开发核查，但正式配置和界面仍限制为当前完整适配版本；发现这些文件不代表发行包已经提供了可用的新版本完整组件。本次核对也发现当前发布路径尚未完整接入上游 4.1.15.13 的启动分支，不能只复制 DLL 或修改版本号启用。

## 本次验证及变更

只读取了本机系统微信 EXE 的版本和数字签名：版本 4.1.15.56，签名有效。没有启动、重启或注入微信，没有读取数据库、采集密钥或发送测试消息。上游报告不是本机实测；本次没有 4.1.15.13 客户端的端到端验收。

更新了版本卡的兼容提示，明确区分“上游基础文字方案”和“本发行完整功能”，并增加 4.1.15.13、4.1.15.56 均不能被旧组件误判为可启动的回归检查。没有新增版本映射或切换用户正在使用的微信。

后续要启用新版，需取得精确匹配的客户端和组件，完成签名/哈希、账号读取、进程交接、真实文字回执及各项媒体能力验证。上游后续增加映射时应重新审查，不能将本次核查当作未来版本的兼容证明。
